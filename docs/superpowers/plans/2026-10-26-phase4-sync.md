# Phase 4 Sync Implementation Plan

> **For agentic workers:** Use the TDD cycle in the current execution session; commit only the scoped Phase 4 changes after verification.

**Goal:** Build the Phase 4 sync CLI, connectors, and atomic snapshot history store.

**Architecture:** `apps/sync` is a TypeScript CLI. Registry parsing remains in Core; a connector registry maps IDs to loaders; all connector outputs and errors pass through one Snapshot validation boundary before atomic storage.

**Tech Stack:** Node 24.22.1, TypeScript, pnpm workspaces, Vitest; built-in Node fetch and filesystem APIs.

**Spec:** `docs/superpowers/specs/2026-10-26-phase4-sync-design.md`

## Global Constraints

- Keep the Core `RegistryEntry` and `Snapshot` contract unchanged.
- Persist under repository-root `snapshots/<entryId>/<ISO timestamp>.json` with atomic temp-file rename.
- Connector failures are per-entry valid error Snapshots; invalid registry fails the run.
- GitHub uses REST with timeout and optional `GITHUB_TOKEN`; never log or store it.
- Local folder reads only immediate children and does not follow symlink children.
- Tests use injected clock/fetch and no real external network.

## Review Focus

- Unsafe registry IDs or symlinked output destinations cannot escape the snapshot root (store tests).
- Invalid connector Snapshot output becomes an error Snapshot (runner tests).
- GitHub error bodies and tokens cannot be persisted in errors (connector tests).
- Child symlinks and nested folder contents are excluded (local-folder tests).
- A failed connector does not block successful concurrent entries (runner/CLI integration test).
